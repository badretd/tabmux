# tabmux fixtures

Checked-in inputs used by unit tests, integration tests, and `scripts/smoke.sh`.
Every feature must have a fixture before it ships (devplan scope guardrail 9).

Fixtures are small, deterministic, and generated by hand or by a documented
script. Do not commit large generated workbooks; `large.xlsx` is produced on
demand by a script in a later phase.

## Text fixtures

| Fixture | Purpose |
|---|---|
| `basic.csv` | Simple header + rows; selection and count |
| `basic.tsv` | Tab-separated variant of `basic.csv` |
| `quoted.csv` | Commas, escaped quotes, CRLF line endings, and a multiline cell |
| `bom.csv` | UTF-8 BOM handling |
| `crlf.csv` | CRLF line endings |
| `semicolon.csv` | Delimiter sniffing |
| `ragged.csv` | Ragged-row policy (short and long rows) |
| `latin1.csv` | Windows-1252/Latin-1 decoding to UTF-8 |
| `data.json` | JSON array of objects |
| `data.jsonl` | JSONL input with nested objects, arrays, and nulls |

## Adding fixtures

1. Keep files tiny unless the phase explicitly calls for a stress fixture.
2. Prefer LF for new text fixtures. `quoted.csv` and `crlf.csv` are
   intentionally CRLF so the CSV reader is tested against both endings.
3. Document the fixture in this table in the same change.
